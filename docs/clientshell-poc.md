# PoC: гибрид attach + одно ClientShell-подключение

Ветка `clientshell-poc`, herdr 0.9.3, флаг `SHEPHERD_CLIENT_SHELL=1`. Без флага Shepherd работает как в main.

## Что в ветке

Панели остаются на attach: путь панелей в `session.rs`, `emulator.rs` и `pane.rs` такой же, как в main. Окно держит одно долгоживущее ClientShell-подключение (`src/herdr/client_shell.rs`, `src/shell/client_shell.rs`), которое делает три вещи, недоступные attach:

1. **Тема.** `ClientShellHostTheme` (fg, bg, 16 ANSI, appearance) уходит сразу после рукопожатия и потом при смене фона темы. Типы `HostThemeUpdate`/`Rgb` в `wire.rs` совпадают с незакоммиченными из main.
2. **Попап плагина.** Из `PaneSurfaceFrame.popup` берутся метаданные (для карточки в `floating.rs`) и ячейки кадра. Ячейки перекодируются в ANSI и уходят в эмулятор вида попапа. Ввод идёт через `ClientShellPopupInput` (клавиши семантически, вставка через `Paste`), закрытие — через `popup.close` (как и раньше). Для этого в `session.rs` добавлен один вариант транспорта `Transport::Popup`; ветки панелей он не затрагивает.
3. **`[[keys.command]]`.** Список из `shell.snapshot.v1` по тому же подключению, запуск через `command.invoke` (как в main). Отдельный popup-watch при флаге не запускается.

Первая версия PoC, где панели рисовались из поверхности herdr, откачена. Её код остался в коммите `dc20566`. Из неё стоит сохранить один замер: задержка «нажатие → изменение экрана» была 2,3 мс у ClientShell против 19 мс у attach (p50); откуда 19 мс — ниже, в разделе «Откуда 19 мс у attach».

Проверено вживую на отдельной сессии herdr (`herdr --session cspoc server`):

- тема окна дошла до herdr: панель на запрос OSC 11 получила `rgb:2323/2121/3636`, то есть фон темы Shepherd;
- попап плагина (`freethinkel.worktree-hooks`, панель `editor`, `placement: "popup"`, 60%×60%) пришёл в поверхности; его кадр — терминал без рамки, 57×19 при поверхности 100×35;
- `ClientShellPopupInput` набрал `ihello` + Esc в nvim внутри попапа, текст появился в кадре;
- attach-панели окна получили свои размеры (38×57).

Попап в самом окне я глазами не видел: к моменту проверки экран был заблокирован и `screencapture` не снимал. Вид попапа — тот же `PaneTerminal` с тем же элементом, что и в main, поменялся только источник кадров.

## Побочные эффекты: замеры

Все замеры сделаны на изолированной сессии. Размер панелей брался изнутри: в каждой панели крутился цикл `stty size`, вывод читался через `herdr pane read`. Attach-контроллеры как у Shepherd держал `probe::hold`, ClientShell-клиента с нужными флагами и подсчётом трафика — `probe::probe` (оба в `src/herdr/client_shell.rs`, `#[ignore]`). TUI herdr запускался как настоящий клиент `herdr --session cspoc` в псевдотерминале (`tui.py`, вместо Ghostty, чтобы не трогать экран), с ответом на OSC 11 цветом `#003300`. Тема проверялась запросом OSC 11 из панели.

### Передний клиент

herdr выбирает передним активный (`surface_active: true`) ClientShell-клиент с самой свежей активностью. Активность ставят рукопожатие, `ClientShellResize`, ввод и запросы через endpoint. Attach-клиенты передними не бывают. От переднего herdr берёт (`sync_foreground_client_state`, `headless.rs:756`):

- `effective_size` — размер его поверхности;
- тему и appearance, хранящиеся на клиенте. Пустая тема тоже применяется: передний клиент без темы стирает тему herdr. Проверено: после клиента без темы панель перестала получать ответ на OSC 11;
- фокус внешнего терминала. `ClientShellFocus{true}` у переднего помечает активный таб herdr просмотренным и глушит его уведомления;
- keymap: применяются серверные привязки, от клиента не зависят.

Наше подключение становится передним сразу после рукопожатия.

### Размеры панелей

| Сценарий | Показанные (attach) | Скрытые таб/workspace |
|---|---|---|
| Только attach 70×30 и 50×30 | 30×70, 30×50 | 40×60 |
| + активный ClientShell 80×24 | без изменений | **24×79** |
| ClientShell отключился | без изменений | остаются 24×79 |
| + неактивный ClientShell | без изменений | без изменений |
| Активный, `ClientShellResize 1×1` | без изменений | **сплющены** |
| Активный, `ClientShellResize 0×0` | без изменений | игнорируется |
| TUI 120×40, затем наш активный 100×35 | без изменений | без изменений (геометрией владеет TUI) |
| Наш 100×35, затем TUI 140×45 (без attach) | панели таба TUI: 42×54 | остаются в нашем размере, 35×99 |
| TUI ушёл | панели таба снова 33×47 (наш размер) | 35×99 |

Пояснения:
- Attach-панели защищены `direct_attach_resize_locks`.
- Пока активный ClientShell-клиент один, herdr раскладывает **все табы всех workspace** под его поверхность (`resize_shell_tab_geometry_to_target`, ветка `app_client_count() == 1`) и обратно их не возвращает.
- Когда клиентов два, каждый влияет только на таб, который смотрит, и только если владеет его геометрией.
- Если поверхность равна сетке Shepherd, скрытые табы заранее получают примерно тот размер, в котором Shepherd их потом покажет. Это скорее плюс.

### Тема рядом с TUI

| Шаг | Ответ OSC 11 |
|---|---|
| Только TUI | `#003300` (TUI) |
| + наш активный клиент с темой `#400000` | `#400000` (наша) |
| Нажатие клавиши в TUI | `#003300` (TUI) |
| Все отключились | остаётся тема последнего переднего |

Тема скачет между клиентами по последнему действию. Приложения в TUI видят цвета Shepherd, пока передний — Shepherd. Для TUI это неприятно, но herdr так задуман: тема принадлежит клиенту, которым пользовались последним. Чтобы Shepherd забирал тему обратно, когда к нему возвращаются, окно при активации шлёт `ClientShellResize` того же размера. По коду это делает подключение передним, но вживую возврат не проверен: экран был заблокирован.

### Невидимое подключение

| Вариант | Попапы | Тема | Размеры | Трафик |
|---|---|---|---|---|
| `surface_active: false` | **не приходят** | не принимается | не трогает | только снапшоты |
| «Импульс»: `client_shell.surface.set {active:true}` → тема → `{active:false}` | — | без TUI принимается и остаётся; рядом с TUI после выключения возвращается тема TUI | на время импульса скрытые табы раскладываются под поверхность | около 26 КБ на импульс |
| Активный, поверхность = сетка окна | приходят | принимается | скрытые табы в размере сетки, пока нет TUI | см. ниже |

Попап, открытый через публичный API (плагин, `command.invoke`), достаётся табу, который у herdr глобально в фокусе (`popup_owner_tab_id = default_shell_target`). Получает его только активный клиент, который смотрит на этот таб. Событий об открытии попапа в API нет (в `events.rs` нет ни одного `popup.*`), в снапшоте попапа тоже нет. Значит, держать подключение неактивным и включать его по событию нельзя: для попапов оно должно быть активным постоянно.

`surface_interest` в welcome — только флаг «сервер умеет `surface_active` и `client_shell.surface.set`», отдельного режима «только попап» нет.

## Откуда 19 мс у attach

Ввод attach запускает в herdr отрисовку, и эхо попадает в кадр только через 16 мс после неё.

Цепочка в коде herdr 0.9.3:

1. `ServerEvent::ClientInput` (ввод attach, `server/headless.rs:2036`) всегда возвращает `true`, то есть «нужна полная отрисовка». `ClientShellPaneInput` возвращает `true`, только если что-то изменилось: передний клиент, геометрия, прокрутка. После обычной клавиши он возвращает `false`.
2. Главный цикл (`headless.rs:520`) рисует сразу, потому что с прошлой отрисовки прошло больше 16 мс. Эхо от программы к этому моменту ещё не пришло, и кадр уходит без него. Время отрисовки записывается (`record_render_attempt`).
3. Эхо приходит через доли миллисекунды, но следующая отрисовка разрешена только через `MIN_RENDER_INTERVAL` = 16 мс (`app/mod.rs:37`, `can_render_now`/`can_present_now`). Кадр с эхом уходит примерно через 18 мс после нажатия.

Замер (`input_paths::attach_echo_latency` в `src/herdr/client_shell.rs`, тестовая сессия). Кадры читает одна и та же attach-сессия, нажатие отправляется двумя путями. Для задержки эха в панели запускалась программа, которая отвечает каждой клавише через N мс (`RUN="python3 slow_echo.py N"`).

| Эхо в панели | Ввод через attach, p50 | Ввод через `ClientShellPaneInput`, p50 |
|---|---|---|
| zsh | 18,4 мс | 2,1 мс |
| сразу (0 мс) | 18,6 мс | 0,7 мс |
| через 2 мс | 18,4 мс | 3,3 мс |
| через 5 мс | 18,4 мс | 7,0 мс |

Через attach задержка одна и та же, от эха не зависит: её задаёт 16-миллисекундный интервал отрисовки. Через ClientShell задержка равна времени эха плюс ~1 мс. Канал вывода в обоих случаях один и тот же (кадры attach), значит дело не в нём, а в отрисовке, которую запускает ввод.

Исправление на стороне herdr — одна строка: в ветке `ClientInput` возвращать не `true`, а изменение прокрутки, как это делает `ClientShellPaneInput`. Собрать herdr с этой правкой я не смог: `libghostty-vt` требует zig, а его на машине нет. Правка не проверена.

Обход на стороне Shepherd без herdr — слать клавиши панелей через `ClientShellPaneInput` по подключению гибрида. Ограничения:
- работает только для панелей таба, на который смотрит наш клиент;
- при открытом попапе herdr такой ввод не принимает;
- каждое нажатие вызывает `claim_shell_tab_geometry`, то есть рядом с TUI забирает у него геометрию таба.

## Попап, который никто не видит

Вживую попап несколько раз зависал: `ctrl+b u` больше ничего не открывал, у плагина в логе было `ui_busy: a popup pane is already open`, попапа не было ни в Shepherd, ни в TUI. Пока он висел, не работали и `ctrl+hjkl`. Лечилось вызовом `popup.close`.

Причина видна в `herdr-server.log`:

1. Попап, открытый через публичный API, достаётся табу, который у herdr в фокусе в момент открытия (`popup_owner_tab_id`). Показывается он только ClientShell-клиентам, которые смотрят на этот таб.
2. Shepherd переключает табы сам и фокус herdr не двигает, поэтому таб в фокусе у herdr может быть не тем, что показан.
3. Через 1,7 с после открытия попапа Shepherd отправил `pane.focus` в другом табе (`MarkSeen`, агент просмотрен). Явная смена фокуса через API переводит все ClientShell-клиенты на новый таб (`focus_all_shell_clients_on_default_target`). Попап остался на старом табе, где его уже никто не видел.

Исправление: перед запуском команды (`[[keys.command]]`, действие плагина из команд или из палитры) Shepherd шлёт по своему ClientShell-подключению `tab.focus` на показанный таб и ждёт ответа. Ответ приходит за ~3 мс; если его нет, ожидание длится не больше секунды. После этого и вид нашего клиента, и фокус herdr указывают на показанный таб. Попап достаётся этому табу, а `MarkSeen` в том же табе его не уводит. Проверено на тестовой сессии (`focus_tab::answered`): клиент на `w1:t1`, `tab.focus` на `w1:t2`, попап, открытый через `herdr plugin pane open`, пришёл клиенту. Вид TUI herdr при этом не меняется, у него свой.

## Ответ на главный вопрос

Полностью безобидным подключение сделать нельзя. Попапы приходят только активному клиенту, а активный клиент:

- становится передним и навязывает herdr свою тему (рядом с TUI тема переключается по последнему действию);
- пока он один, раскладывает скрытые табы под свою поверхность;
- при выводе в табе, который у herdr в фокусе, получает полные кадры: ~1,3 МБ/с и +3% CPU сервера.

Всё это уже есть в main: popup-watch из `src/herdr/popup.rs` — такой же активный клиент без темы. Значит, пока он передний, он стирает тему herdr. Незакоммиченный `push_host_theme` подключается на миг, ставит тему и уходит. После этого передним снова становится popup-watch, и, судя по коду (`promote_latest_remaining_client` → `sync_foreground_client_state`), тема снова пустая. В сочетании с main я это вживую не проверял, но то, что клиент без темы её стирает, проверено.

## Рекомендация

Гибрид — да, как замена popup-watch и короткого подключения для темы, а не как дополнительное подключение. Одно активное подключение с поверхностью размером в сетку окна:

1. Тема уходит сразу после рукопожатия и при каждой смене (сделано). Так передний клиент Shepherd никогда не бывает без темы.
2. Без `ClientShellFocus`: он трогает «просмотрено» и уведомления. `tab.focus` — только перед запуском команды (сделано, см. «Попап, который никто не видит»), а не при каждом переключении таба: он двигает глобальный фокус herdr.
3. При активации окна — `ClientShellResize`, чтобы herdr вернул тему Shepherd. Сделано, но вживую не проверено.
4. Поверхность всегда равна сетке окна, никаких маленьких или нулевых размеров.
5. Трафик при выводе в фокусном табе принять как цену попапов. Если он станет заметен (удалённые машины через relay), есть два пути: включить `surface_delta`/`surface_reuse` и научиться находить в этих кодировках попап, либо попросить у herdr «интерес только к попапу» или событие об открытии попапа. Тогда подключение можно держать неактивным.

Чего не сделано: живой проверки попапа в окне и возврата темы при активации окна, замера расхода Shepherd на декодирование поверхностей, ввода мышью в попап (код маппинга есть, не проверялся).
